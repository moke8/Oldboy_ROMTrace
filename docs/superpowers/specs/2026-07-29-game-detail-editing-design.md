# 游戏详情编辑与多目标保存设计

## 目标

将现有只读游戏详情弹窗改为可编辑界面。用户保存后，程序沿用主界面现有配置，分别更新 Pegasus、`gamelist.xml` 与 Anbernic `Imgs` 封面副本，并安全处理封面、Logo 和视频的上传、替换与移除。

## 编辑范围

详情弹窗允许编辑以下元数据：

- 标题
- 游戏 ID
- 开发商
- 发行商
- 类型
- 玩家数
- 发售日
- 评分
- 简介

ROM 路径保持只读。封面、Logo 和视频分别支持选择本地文件、预览替换结果和移除当前媒体。

## 保存目标

弹窗不维护独立配置，而是读取当前平台页和全局设置中已经生效的选项：

- `Pegasus`：更新 `metadata.pegasus.txt`
- `gamelist.xml`：更新 EmulationStation 元数据
- `兼容 Anbernic 封面`：更新 `Imgs/<ROM文件名>.<图片扩展名>`

弹窗显示当前保存目标，便于用户在保存前确认。未勾选的目标保持原样，不删除已有记录或文件。`Imgs` 只保存封面副本，不保存 Logo 或视频。

## 界面设计

详情弹窗保留左侧媒体区域与右侧元数据区域。元数据值改为输入控件，简介使用多行文本框，ROM 路径使用只读输入框。

封面、Logo 和视频各自提供“选择文件”和“移除”操作。选择文件后立即更新预览；视频继续使用现有 Qt Multimedia 播放能力。底部提供保存与取消按钮，并展示本次保存将应用到哪些目标。

保存成功后关闭弹窗并重新加载当前游戏展柜，使卡片和再次打开的详情立即反映新数据。取消关闭弹窗时不改动任何索引或媒体文件。

## 架构

`GameDetailDialog` 只负责编辑状态、输入校验、媒体选择和构造保存请求。平台页负责把当前游戏目录、Pegasus/gamelist 复选框状态和全局 Anbernic 配置传入弹窗，并在保存成功后刷新展柜。

新增独立的单游戏保存服务，负责：

1. 规范化编辑后的元数据。
2. 校验 ROM 文件名、游戏目录和待上传媒体。
3. 将新媒体复制到临时文件。
4. 根据启用的目标更新单个游戏的 Pegasus 和 gamelist 记录。
5. 根据 Anbernic 配置创建或更新 `Imgs` 封面副本。
6. 所有目标写入成功后替换正式媒体，并清理被替换或移除的旧媒体。
7. 返回更新后的展示数据或明确错误。

Pegasus 与 gamelist 的格式转换复用现有字段和写入规则，但单游戏保存逻辑提供清除字段的能力，确保用户移除媒体或清空可选元数据时，对应字段也能从已启用的索引中移除。

## 媒体路径与删除规则

新媒体统一保存到：

- `media/<ROM文件名>/boxfront.<原扩展名>`
- `media/<ROM文件名>/logo.<原扩展名>`
- `media/<ROM文件名>/video.<原扩展名>`

上传动作复制用户选择的文件，不移动或删除原始上传源文件。若新文件与目标路径相同，则不重复复制。

旧媒体仅在保存全部成功后删除，并同时满足以下条件：

- 文件位于当前游戏目录内部。
- 文件是本次被替换或移除字段的旧值。
- 文件不再被其他游戏的 Pegasus 或 gamelist 记录引用。
- 文件不是新保存媒体的最终路径。

移除封面时，若启用了 Anbernic 兼容，则删除该游戏对应的 `Imgs` 封面；未启用时保持既有 `Imgs` 文件不变。替换封面且启用 Anbernic 兼容时，使用新封面覆盖对应副本。

## 一致性与错误处理

保存服务先完成输入校验与临时媒体准备，再生成各目标的新内容。索引写入继续使用现有备份机制。正式媒体替换和旧媒体删除安排在目标内容成功写入之后，降低半完成状态风险。

若校验、复制或索引写入失败，弹窗保持打开并显示错误；不会删除旧媒体。已创建的临时文件会被清理。若保存目标全部关闭，则拒绝保存并提示用户先启用至少一个目标，避免用户误以为数据已持久化。

## 测试

测试覆盖：

- 详情弹窗展示可编辑字段、只读 ROM 路径和当前保存目标。
- 编辑元数据后仅更新启用的 Pegasus/gamelist 目标。
- 清空字段会从启用的索引中移除对应值。
- 上传、替换和移除封面、Logo、视频。
- 启用 Anbernic 时创建、覆盖或移除 `Imgs` 封面。
- 未启用的索引与 `Imgs` 保持不变。
- 不删除游戏目录外的上传源文件。
- 不删除仍被其他游戏引用的媒体。
- 保存失败时保留旧索引和旧媒体，并清理临时文件。
- 保存成功后刷新展柜并显示更新内容。
